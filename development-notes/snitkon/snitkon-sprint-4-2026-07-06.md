# Sprint 4: HTTP, RxJS & Testing — 2025-07-06

- **What was done:** Designed and implemented a lightweight, modern, and reactive toast notification system from scratch, avoiding heavy third-party libraries. Developed a centralized ToastService utilizing Angular Signals (signal, asReadonly, and update) to manage the notification state slice immutably and performantly. Refactored the presentation layer into a standalone ToastComponent configured with ChangeDetectionStrategy.OnPush, binding directly to the read-only signal stream in the template. Implemented smooth enter/leave transitions using the @angular/animations framework, declaring a dynamic @toastAnimation trigger to animate incoming and outgoing alerts seamlessly. Integrated semantic HTML structure, dynamic styling via NgClass for multiple toast types (success, error, warning, info), and built a pure CSS-driven time-progress indicator (.toast-loader) synchronized with the service lifecycle.
- **Problems:**
    * Encountered a framework deprecation warning where the traditional trigger(name, [...definitions]) signature was flagged as obsolete, requiring an update to the modern configuration-object-based API signature.
    * Experienced a layout break where the custom CSS progress loader (@keyframes loader) failed to render because of a syntax mismatch between the HTML kebab-case class declaration and the SCSS parent-selector (&-loader) nesting output.
    * Faced an asynchronous race condition where toasts disappeared instantly or failed to animate completely because the service-level setTimeout garbage collection was set to 300ms, prematurely destroying the DOM element before its :enter or :leave animation lifecycles could finish their 300ms ease-out transitions.
    * Faced a change detection issue in the OnPush component when trying to use raw array mutations (push), which left the memory reference identical, preventing Angular from tracking collection changes and executing :leave animations correctly.
- **Solutions:**
    * Updated the animation declaration to comply with the latest Angular standards by migrating to the new signature, passing the animation array wrapped inside the definitions property of the configuration object: trigger('name', { definitions: [...] }).
    * Synchronized the template and styles by refactoring the loader markup to use a consistent .toast-loader class, enabling proper CSS compilation and correct keyframe application over a 3-second lifecycle.
    * Adjusted the service-level automatic destruction timer to 3000ms, matching the visual duration of the CSS loader, which gave the Angular Animation player enough breathing room to fully execute both the entry and exit transitions.
    * Fully transitioned the state architecture from BehaviorSubject and manual ChangeDetectorRef.markForCheck() invocations to modern Angular Signals. Leveraged the immutable .update() method with the spread operator ([...currentToasts, toast]) to guarantee a new array reference on every state mutation, enabling seamless @for block tracking via track toast.id.
- **What I learned:**
    * Mastered the latest @angular/animations API design, understanding how moving definitions into a configuration object prepares the engine for future feature extensions without breaking change signatures.
    * Deepened my understanding of how Angular's declarative control flow (@for) interacts with the Animation Engine, recognizing that tracking a unique primitive (toast.id) rather than the entire object reference is vital for the framework to isolate and execute :leave DOM-destruction animations.
    * Realized the operational benefits of Signals over RxJS for pure component presentation states, eliminating the need for ngOnInit hooks, manual subscription management, and DestroyRef cleanup boilerplate while maintaining strict OnPush efficiency.
    * Learned how to orchestrate and synchronize micro-interactions between asynchronous TypeScript macros (setTimeout), Web Animation APIs (Angular transitions), and CSS3 Keyframes to create a polished user experience.
- **Plans:** Extend the notification subsystem to support dynamic configuration overrides per invocation (e.g., custom durations, closable flags, action buttons), implement accessible ARIA live regions (role="alert") for screen readers, and add a staggering effect for simultaneous notifications using query() and stagger() animation utilities.
- **Time spent:** 6 hours.
