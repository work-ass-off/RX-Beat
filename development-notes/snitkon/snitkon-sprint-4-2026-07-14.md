# Sprint 4: HTTP, RxJS & Testing — 2025-07-14

- **What was done:** Designed and implemented a robust unit testing suite for complex reactive architectural units using Vitest and Angular TestBed.
    * Covered the JamendoAbstractService to verify the integration between Angular Signals and RxJS streams (toObservable). Tested dynamic parameter mapping, ensuring namesearch queries are conditionally appended to HTTP requests only when search queries are non-empty and sanitized via .trim().
    * Wrote isolation tests for SidebarService to assert synchronous reactive state transitions utilizing writable signals and .update() methods.
    * Developed a targeted testing strategy for the LanguageDirective, asserting internationalization logic (TranslateService) and reactive computed-signal states without the overhead of rendering host templates, by exploiting TestBed.runInInjectionContext.
- **Problems:**
    * Asynchronous Deadlocks (Microtask Queue): Faced severe test timeout errors (5000ms limit) when using firstValueFrom in tests involving toObservable. Since toObservable relies on an asynchronous microtask to emit its first value, the execution stalled permanently as firstValueFrom blocked the JS event loop before Angular could run its change detection cycle.
    * TypeScript Signature Mismatch in Mocks: Encountered compilation errors when attempting to use .set() on a mocked Signal. Because the public API of the mocked service exposed a read-only Signal<string>, TypeScript rightfully blocked mutative operations in the test body.
    * catchError Testing Pitfalls with EMPTY: Experienced test hangs and unhandled exceptions when testing HTTP error states. Because the production catchError block gracefully intercepted failures and returned EMPTY, firstValueFrom rejected with an EmptyError, failing to resolve the promise.
    * Missing Injection Context (NG0203): Ran into runtime injection context errors when testing the LanguageDirective class directly via new LanguageDirective(). Because the directive internally uses modern inject() and toSignal() functions, standard constructor instantiation failed due to the lack of an active injector context.
- **Solutions:**
    * Leveraging Virtual Time Control: Replaced problematic async/await and firstValueFrom patterns in asynchronous reactivity tests with fakeAsync zones combined with manual tick() calls and TestBed.flushEffects(). This synchronized Angular’s internal signal microtask queue with RxJS subscription lifecycles.
    * Exposing Writable Signal References: Refactored mock declarations inside tests. Created a local private WritableSignal (_writableSearchSignal) and exposed it in the mocked service as a read-only view (asReadonly()). This allowed tests to mutate the signal value cleanly via the writable reference while preserving the read-only signature on the mocked service.
    * Synchronous Subscription Assertions: Rewrote the catchError test to bypass promise resolution entirely. Subscribed to the target stream synchronously, using TestBed.flushEffects() to force immediate execution, and asserted assertions (verifying toastService.error calls) inside the stream’s complete callback.
    * Injection Context Mocking: Resolved the NG0203 error by configuring the directive as a provider in TestBed.configureTestingModule and instantiating it inside a TestBed.runInInjectionContext(() => new LanguageDirective()) block, providing a mock implementation of TranslateService.
- **What I learned:**
    * Understood Signal-to-Observable Timing: Deepened my knowledge of the asynchronous nature of toObservable, realizing that it does not immediately emit values upon subscription but registers a microtask, making TestBed.flushEffects() and fakeAsync/tick indispensable for predictable test flows.
    * Mastered Mocking Reactive Streams: Learned how to correctly mock complex RxJS error pipelines using throwError, ensuring the mock accurately mimics raw HTTP errors (HttpErrorResponse) rather than mapping values prematurely.
    * Isolating Directives with runInInjectionContext: Discovered a powerful Angular testing paradigm: you don't always need a heavy TestHostComponent to test directive logic. If you only need to assert signal states and class methods, executing the constructor inside runInInjectionContext keeps the test suite lightning-fast.
    * Handling Empty Streams: Solidified my understanding of EMPTY stream behavior in RxJS, and learned how to safely test completed, non-emitting streams using synchronous subscriptions or the .pipe(defaultIfEmpty(...)) operator in test suites.
- **Plans:** Implement a comprehensive integration test suite using TestHostComponent for the LanguageDirective to assert real DOM events (clicking the host element and verifying host bindings), integrate mock service validation for deep routing guards, and add coverage reporting to the CI/CD pipeline using Vitest UI.
