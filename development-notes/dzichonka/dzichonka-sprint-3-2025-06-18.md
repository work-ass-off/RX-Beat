Так что впереди, возможно, ждёт небольшой рефакторинг нейминга. А как известно, в программировании есть 2 сложные задачи:

- кеширование
- и выбор названий 😄

### NgRx: планы изменились

Изначально мы планировали использовать NgRx как хранилище данных, приходящих из Jamendo.

На бумаге это выглядело красиво.

На практике оказалось, что архитектура Jamendo API довольно специфична:

разные эндпоинты возвращают разные структуры данных
запросы часто независимы друг от друга
универсальный стор для всех ответов быстро превращается в монстра

В какой-то момент стало понятно, что:

по сути каждый запрос требует собственного состояния

А это уже выглядит как борьба со стором ради самого стора.

Поэтому решение поменялось.

Сейчас планируем использовать NgRx только для тех данных, которыми действительно владеем сами:

Playlist
возможно Library
данные нашего backend

Такое решение выглядит намного чище и практичнее.

Небольшая техническая грусть
